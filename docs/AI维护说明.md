# 不会写代码，也能接着维护

把整个 `isab-journal` 文件夹交给能够编辑本地文件的 AI。不要只给一个网页截图，也不要只交接 `dist`。不需要继承上一位负责人的 AI 账号。

## 直接复制给 AI

> 请先阅读这个文件夹里的 README.md、AGENTS.md 和 docs/AI维护说明.md。我要更新 ISAB 生活学习小刊。请按我的要求修改 content 中的文章，保留学生独立整理的口吻；可以链接学校资源，但不要写成学校官方。核对新增事实的原始来源，区分文字编辑日期和资料核对日期。完成后生成网页、运行检查并打开本地预览，告诉我改了哪几篇。当前只做本地预览，不发布、不迁移账号。
>
> 本次要改的内容：……
>
> 我提供的资料或链接：……

增加文章时补一句：“请复制文章模板，新建一篇中文笔记；若能完成可靠翻译，也添加英文版。不要改已有文章的地址。”

修正旧价格时补一句：“只更新查到的项目，找不到证据的标为待确认，不要猜数字，不要把所有文章的核对日期改成今天。”

## 文稿开头那几行是什么

| 字段 | 怎么填 |
| --- | --- |
| `lang` | 中文 zh、英文 en；原有其他语言按文件夹标识 |
| `kind` | 新资源用 resource；原文章保留原值 |
| `slug` | 稳定的英文短名，只用小写字母、数字、短横线；发布后不要随意改 |
| `category` | study 学习、food 吃饭、home 安顿生活、move 通勤、weekend 休闲、care 支持、events 活动 |
| `title` | 文章标题，像向同学解释一件事 |
| `summary` | 列表中显示的简短介绍 |
| `takeaway` | 文章开头“先看这几句”的重点 |
| `edited` | 这次真正改动文稿的日期，YYYY-MM-DD |
| `checked` | 最近真正核查资料的日期；排版不等于核查 |
| `site` / `url` | 资源网站名称和 HTTPS 链接；不需要时可省略 |
| `cost` / `login` | 免费范围和账号条件；未核对时明确说不确定，或省略 |
| `tags` | 用逗号隔开的搜索词 |
| `cover` | 可选，如 assets/photos/iowa-winter.jpg；配 cover_alt 与 cover_caption |
| `related` | 可选，相关文章的 kind/slug，用逗号隔开 |
| `event_end` | 活动这一期的最后一天；过期后自动显示往期回顾 |
| `event_status` | 确认已结束但无准确日期时填 past；其他情况省略 |

这些行都只写一行文本，不要加引号、缩进或多行格式。正文从第二个 `---` 下面开始。模板文件留在 docs，不会自动被当成文章。

## 正文怎么写

写短段落，用 `## 小标题` 分节。链接写作 `[名字](https://网址)`。列表每行以 `- ` 开头。需要图片时另起一行写 `![图片说明](/assets/文件名.jpg)`，同时保存图片来源与许可。网页截图会收进可展开的参考区。

不必手改目录、搜索结果或相关文章网页。AI 生成后，它们从文稿自动更新。首页“最近更新”按 edited 日期选取；“先解决一件小事”和季节栏目由 `theme/editorial.json` 维护。没有译文的文章会使用已有语言，并显示语言标记。

## 每次完成后，你只要看这些

打开首页，再打开改过的文章：标题是不是自然？重点够不够短？链接点开是不是正确的网站？价格、日期、资格有没有来源？把窗口缩窄，文字和按钮是否仍能读？如果是英文版，含义是否和中文版一致？

资料核对通过后，再决定什么时候上线。不要把密码、恢复码、私人邮箱或成员名单贴给 AI，也不要写进文章文件。AI 只需要看到公开内容和技术说明。

## 换届时交什么

把整个项目文件夹打包，另存一份到社团能长期控制的位置。让接任者使用自己的工具打开、改一段文稿、启动预览，确认可以独立操作。发布账号的权限和恢复方式另行交接；文稿里不记录秘密信息。需要恢复旧内容时，从上次备份取回对应文稿和图片，再生成网页。
