# 给下一任：接手文件与更新网站

先看根目录的 [从这里开始.txt](../从这里开始.txt)。不用会写代码；维护者负责内容判断和预览确认，AI 协助修改文件与检查。

## 接手时拿到什么

| 交接物 | 用途 |
| --- | --- |
| 社团 GitHub 资料库的固定链接 | 建立后作为最新文稿、图片和维护说明的来源 |
| 当前网站的公开网址 | 对照实际线上内容，确认发布是否成功 |
| 完整的 `isab-journal` 文件夹备份 | 即使原负责人的电脑和 AI 账号不可用，也能接着维护 |
| 自己的管理权限 | 能保存修改、发布，并在换届时邀请下一任 |

当前状态（2026-11-06）：社团组织与资料库已建立，正在上传项目并验证首次发布；第二位管理员和下一任的权限交接仍待安排。设置步骤见 [GitHub 发布与恢复](GitHub发布与恢复.md)。当前备份不包含任何账号的控制权。

交接包保留完整可编辑源文件；不包含自动生成的 `dist` 网页。启动预览时会重新生成，无需另找上一任索取。

## 平时怎么用 AI

1. **取得最新文件。** 资料库建立后，每次从那里打开最新版本。工具如果支持连接 GitHub，授权它访问该项目；否则下载最新项目，在能编辑本地文件的 AI 中打开。仅能读取链接的工具可能无法保存修改。
2. **说清楚这次要改什么。** 使用 [AI 维护说明](AI维护说明.md) 的提示词，附资料或链接。AI 先读项目说明，再改对应文稿。
3. **看预览。** 请 AI 生成网页、运行检查并打开本地预览。人工确认文字是否自然、事实有无依据、链接是否正确。
4. **保存版本。** GitHub 建立后，把源文件的修改保存到同一个资料库，并写一句改动说明。没有接入资料库的工具，需要把改好的完整文件交还并由有权限的人保存。保留修改前的版本。
5. **确认发布。** 首次搭建时配置清楚什么操作会更新线上网站，维护者确认后才执行。发布之后打开真实网址，检查改动确实出现；生成成功或保存文件成功不等于线上发布成功。

已经搭好后，下一届通常继续更新同一个网站，不需要每年重建。若 AI 无法连接账号，可在本地完成编辑与检查，再由有权限的维护者完成平台上的发布操作。

## 首次上线还需要完成的准备

这些是待实施事项，不是当前已经具备的功能：

- 将本项目放进社团拥有的 GitHub 组织资料库，设置至少两位现任管理员。
- 选择正式网址与发布方式。GitHub Pages 可作为候选；公开资料库适用其免费方案。只上传适合公开的网站资料，不上传账号登记表或登录截图。
- 配置生成、检查、发布流程。建议先保存待审核的修改，预览通过后再发布，避免维护者仅保存草稿就意外改变线上网站。
- 本项目目前使用网站根路径。可使用 `组织名.github.io` 形式的组织站点；如果选 `组织名.github.io/资料库名/`，需要先适配子路径，不能直接沿用当前生成结果。
- 确定正式网址后，使用生成工具的 `--public-url` 参数配置正式链接和搜索收录，并检查全部页面。不要直接把默认禁止收录的预览结果当正式版发布。
- 记录一次成功发布的版本，并演练恢复到上一版。确认发布过程不依赖离任者的私人授权或电脑。

[GitHub Pages 官方说明](https://docs.github.com/en/pages/getting-started-with-github-pages/what-is-github-pages)

## 每年邮箱更换时

社团组织和网站资料库保留，成员权限和当届联系邮箱更新。组织不是共享邮箱；各管理员使用自己的账号登录，网站文件归组织所有。[GitHub 组织说明](https://docs.github.com/en/organizations/collaborating-with-groups-in-organizations/about-organizations)

先邀请接任者成为管理员，确认能独立访问，再更新适用的联系、通知及恢复安排。至少保留两位现任管理员。旧邮箱和旧管理员在交接演练完成前保持可用；成功后再移除离任者。[GitHub 管理连续性建议](https://docs.github.com/en/organizations/managing-peoples-access-to-your-organization-with-roles/maintaining-ownership-continuity-for-your-organization)

文件备份和账号权限要分别交接。不要把密码、恢复码或个人信息写进公开项目；内部交接登记另行保管。AI 账号也由接任者自行选择，网站不需要继承原负责人的 AI 订阅。

## 怎样算真正交接成功

接任者在自己的电脑、自己的 AI 工具和自己的管理权限下完成一次演练：找到最新文件，修改一段话，看预览，经确认发布，检查公开页面，再恢复原内容。另一位管理员也能访问并接管。离任者无需提供验证码或代为登录。

需要恢复时，先保存当前文件，再让 AI 取回指定的旧版本、生成预览并检查；确认后按同一发布流程恢复线上页面。不要未经比较就用旧压缩包覆盖整个最新资料库。
